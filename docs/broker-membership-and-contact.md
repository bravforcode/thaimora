# ส่งมอบระบบนายหน้าและการติดต่อเจ้าของประกาศ — 4 ตุลาคม 2026

เตรียมระบบสมาชิกนายหน้า **US$25 ต่อเดือน (USD)** และส่งคำถามจากผู้สนใจถึงผู้ลงประกาศของทรัพย์นั้นผ่านอีเมล/LINE แล้ว การเข้าถึงแดชบอร์ดเปิดเมื่อเซิร์ฟเวอร์ยืนยันการชำระเงินปัจจุบันสำเร็จ **ไม่มีขั้นอนุมัติสมาชิกจากแอดมิน** แอดมินยังตรวจสิทธิ์และอนุมัติการเผยแพร่ประกาศตามเดิม

ขณะส่งมอบ **การเรียกเก็บเงิน การส่งข้อความ และการเชื่อม LINE ยังปิดอยู่** รอเชื่อมบัญชีจริงและทดสอบกับบัญชีนั้น ฐานข้อมูล/API ที่ติดตั้งแล้วไม่ได้หมายความว่าหน้าเว็บสาธารณะเปิดใช้งานแล้ว ดูขอบเขตหลักฐานที่ [บันทึกการตรวจ](reviews/broker-contact-review.md) และขั้นตอนเซิร์ฟเวอร์ที่ [broker-backend.md](broker-backend.md)

## การใช้งานที่เตรียมไว้

| ผู้ใช้ | ขั้นตอนและผลลัพธ์ |

## การส่ง contact

1. ผู้สนใจเปิดทรัพย์จริง กรอก contact และยินยอมให้ส่งข้อมูลคำถามแก่ผู้ลงประกาศนั้น ฟอร์มเดิมยังมี Turnstile, rate limit และ idempotency key
2. เซิร์ฟเวอร์เลือกผู้รับจากการผูกเจ้าของประกาศ ไม่รับอีเมลหรือ LINE ID ปลายทางจากผู้สนใจ
3. บันทึกคำถามและงานส่งแยกตามผู้รับ/ช่องทาง เฉพาะช่องทางที่ผู้รับยินยอมไว้ สำเนาถึงทีมงานใช้ outbox แยกจากงานส่งเจ้าของ
4. ก่อนส่งทุกครั้ง ตรวจผู้รับปัจจุบัน ความยินยอม อีเมลที่ยืนยันแล้ว/LINE ที่เชื่อมอย่างถูกต้อง และสถานะประกาศอีกครั้ง งานเก่าที่สิทธิ์เปลี่ยนถูกยกเลิก
5. `queued` คือบันทึกงานรอส่ง; การตอบรับจากผู้ให้บริการไม่ใช่หลักฐานว่าผู้รับอ่านหรือได้รับข้อความแล้ว รายละเอียด retry/เวลาหมดอายุและข้อจำกัดระหว่างคำขออยู่ใน runbook

เจ้าของที่ไม่ได้เป็นสมาชิกนายหน้าก็รับคำถามที่ได้รับอนุญาตได้ ผู้รับยกเลิกช่องทางทั้งหมดหรือ unlink LINE ได้แม้สมาชิกหมดอายุ ไม่มีการส่งข้อความหาผู้ลงประกาศเองโดยไม่มี contact จากผู้สนใจ

LINE ใช้ **LINE Official Account Messaging API** ผู้ใช้เพิ่มเพื่อน OA ส่ง `link` เข้าบัญชีเว็บ แล้วใช้หน้าผูกบัญชีของ LINE พร้อม nonce และ webhook ที่ตรวจ signature การผูกบัญชีไม่เปิดรับ notification เองจนกว่าจะยินยอม ไม่มีช่องให้กรอก LINE user ID ของผู้อื่น

## บัญชีและข้อมูลที่ต้องส่งก่อนเปิดจริง

ส่งค่าลับผ่านไฟล์ environment ที่ไม่เข้า Git หรือช่องจัดการ secret ของเจ้าของบัญชี ห้ามใส่ในแชต โค้ด รูปหน้าจอ หรือค่า `NEXT_PUBLIC_*`

| รายการ | ต้องเตรียม |
| --- | --- |
| Stripe | บัญชีของผู้ว่าจ้าง, test/live secret และ webhook secret แยกกัน, Price **2500 USD minor units ต่อเดือน** ที่ตรงโหมด, Billing Portal และ event subscriptions |
| อีเมล | Resend account/key และโดเมนผู้ส่งที่ยืนยันแล้ว; `INQUIRY_EMAIL_FROM`; Supabase Auth SMTP/verification/recovery ที่ทดสอบแล้ว |
| LINE | OA ของผู้ว่าจ้าง, Messaging API channel access token/secret, friend URL, webhook URL และผู้ใช้สำหรับทดสอบ account link/unfollow |
| Origin | HTTPS origin ของหน้าเว็บที่ได้รับอนุมัติ, CORS และ Supabase signup/redirect origins ตรงกัน; `BROKER_APP_URL` ไม่รับจากผู้ใช้ |
| เงื่อนไข | ข้อความ EN/TH เรื่อง subscription, การต่ออายุ/ยกเลิก/คืนเงิน และ privacy/contact consent ที่อนุมัติแล้ว พร้อม terms version; ค่าปัจจุบันยังไม่ตั้ง terms version |
| ข้อมูลทรัพย์ | ประกาศจริงพร้อมสิทธิ์เผยแพร่ รูปที่มีสิทธิ์ และบัญชีผู้รับที่ยืนยันแล้ว; ผูกผู้รับและรับความยินยอมก่อนทดลอง contact |

## ลำดับเปิดระบบ

1. ตั้ง server secrets ตาม [Account setup and activation](broker-backend.md#account-setup-and-activation) โดยคง `BROKER_BILLING_ENABLED=false`, `CONTACT_DELIVERY_ENABLED=false` และ `LINE_LINK_ENABLED=false` ระหว่างตั้งค่า
2. ตั้ง Price/terms/mode ใน private configuration ตรวจราคา **US$25/month** ทั้งจาก Stripe และ API โหมด test ต้องไม่ผูก customer เดิมกับโหมด live; ใช้กระบวนการเปลี่ยนโหมดใน runbook
3. ทดสอบสมัคร/ยืนยัน/กู้บัญชี, การชำระสำเร็จ เปิดแดชบอร์ดทันที, ชำระล้มเหลว, renewal, expiry, cancellation, refund/dispute, portal และการปฏิเสธอ่านข้อมูลข้ามบัญชี ด้วยบัญชี Stripe test จริง
4. ทดสอบ LINE link, nonce/replay, unfollow/unlink และ email opt-in/withdrawal; ทดลอง contact จากผู้สนใจถึงเจ้าของที่อนุญาต พร้อมตรวจผล outbox และ provider receipts แยกกัน
5. ตรวจ backup/restore ที่รวมตาราง private ใหม่ และการตั้งแอดมิน/กฎหมาย/สิทธิ์ข้อมูล/hosting ตาม launch gates เดิม ทดสอบเบราว์เซอร์กับ origin จริงก่อนเปิดสาธารณะ
6. เมื่อบัญชีจริงและเงื่อนไขพร้อม และการทดสอบผ่าน จึงเปิด billing ทั้ง environment และ database; เปิด LINE และ contact delivery ตามผลทดสอบ แล้วเปิด scheduler เฉพาะงานส่ง contact ด้วยคำสั่ง service-only ใน runbook
7. ตรวจ cron HTTP outcomes, งาน due/failed/canceled และเหตุการณ์ Stripe หลังเปิดจริง หากจำเป็นให้ปิดสวิตช์ของระบบที่มีปัญหาโดยเก็บประวัติและหลักฐานไว้

## สถานะส่งมอบ

Migration นายหน้า/contact 06–09 ติดตั้งใน Supabase ของ Thaimora แล้ว การตรวจ SQL ทั้งชุดหลักและกรณี upsert เฉพาะแบบ `BEGIN`/`ROLLBACK` ผ่านหลังแก้ข้อจำกัด LINE; fixture ที่ติดตามเหลือศูนย์ APIv7, `stripe-webhook`, `line-webhook` และ `deliver-contact` v1 ACTIVE การตรวจ HTTP จริงผ่าน18/18 โดยยืนยันราคาและการปฏิเสธเข้าข้อมูลส่วนตัว/คำขอที่ไม่ได้รับอนุญาต ขณะนี้ **สมัครนายหน้า เรียกเก็บเงิน ส่ง contact และเชื่อม LINE ยังปิด** การตอบ503 ของ webhook ขณะไม่ตั้งบัญชีไม่ใช่ผลทดสอบ signature กับบัญชีจริง ผลเบราว์เซอร์โค้ดล่าสุดบันทึกแยกใน review

ยังไม่มี Stripe product/Price/customer/charge จริงจากการเตรียมงานนี้ ไม่มีการส่งอีเมล/LINE จริง หน้าเว็บสาธารณะยังไม่ได้ deploy: สิทธิ์ใช้ Vercel เชิงพาณิชย์ ข้อมูลจริงที่มีสิทธิ์ ข้อความกฎหมาย/แอดมินที่อนุมัติ การทดสอบผู้ให้บริการ และ recovery ปัจจุบันยังเป็นเงื่อนไขก่อนเปิด ไม่ใช้ผล fixture/mock แทนการตรวจเหล่านี้

การตรวจโค้ดล่าสุดผ่าน typecheck/lint, unit80/80 และ Chromium นายหน้า11/11 แบบ fixture รวมภาษาไทย/อังกฤษและการปิดข้อมูลส่วนตัวเมื่อหมดสิทธิ์; ตรวจ retry contact เดิมอีก1/1 ผ่านโดยรักษาฟอร์ม/idempotency และทดสอบ consent ที่เพิ่มแล้ว build แบบ preview ผ่าน80 generated pages พร้อมตรวจ language ของ79 HTML ตัวอย่างหน้าที่ส่งมอบอยู่ใน [หน้าสมัครบนมือถือภาษาไทย](evidence/broker-recruitment-th-mobile.png) และ [แดชบอร์ดภาษาอังกฤษ](evidence/broker-dashboard-en.png) ภาพใช้ข้อมูลทดสอบและไม่ใช่หลักฐานบัญชีผู้ให้บริการจริง หลักฐานฐานข้อมูล/เวอร์ชันและการล้าง fixture ล่าสุดอยู่ใน [feature-hosted-database.json](evidence/feature-hosted-database.json)

หลังรีวิวท้ายสุด แก้การอ่านหลักฐานเจ้าของ/สิทธิ์รูปที่แอดมินล้างเป็น `null` ให้แก้ร่างต่อได้ โดยไม่ลดเงื่อนไขตรวจสิทธิ์ก่อนบันทึก/เผยแพร่ ตรวจ broker API16/16 ซึ่งเป็นส่วนหนึ่งของชุด unit เดิม พร้อม typecheck/lint/build ของโค้ดหลังแก้ ผ่านทั้งหมดที่ archive `8f7c8d6cba4f712b` หลักฐาน80-unit และเบราว์เซอร์ข้างต้นเป็น candidate ก่อนแก้กรณีนี้; layout ไม่เปลี่ยนและไม่ต้อง deploy backend เพิ่ม

## สมาชิกเจ้าของทรัพย์และแดชบอร์ดรายงาน — 27 ตุลาคม 2026

- หน้า `/owner/` และ `/th/owner/` สำหรับเจ้าของทรัพย์ ค่าสมาชิกรายเดือน **US$25** เท่ากับนายหน้า ใช้ Stripe Price เดียวกัน ไม่มีแพ็กเกจฟรี
- บัญชีเจ้าของต้องให้แอดมินตรวจความเป็นเจ้าของก่อนเปิดสิทธิ์ (ค่าเริ่มต้น `owner_approval_required = true`) แม้ชำระเงินแล้วก็ยังไม่เปิดสิทธิ์จนกว่าจะอนุมัติ บัญชีนายหน้ายังไม่ต้องอนุมัติตามเดิม
- แดชบอร์ดรายงานของนายหน้าและเจ้าของ แสดงสรุป KPI (การเข้าชม คำถาม การกดติดต่อ คำถามที่ยังไม่ตอบ และเวลาตอบค่ากลาง) แนวโน้มรายวัน ผลรายประกาศ และรายการคำถามพร้อมสถานะและเวลาที่ใช้ตอบ เลือกช่วง 7 / 30 / 90 วันตามเวลาประเทศไทย
- ส่งออก CSV ได้ทั้งคำถามและผลรายประกาศ ไฟล์เปิดใน Excel ได้ไม่เพี้ยนภาษาไทย ไฟล์คำถามจำกัด 10,000 แถว หากเกินระบบไม่ส่งไฟล์บางส่วน แต่แจ้งให้ลดช่วงเวลา
- ข้อจำกัดที่ยังมี: ลิงก์กลับจากหน้าชำระเงินยังชี้ไป `/broker/dashboard/` สำหรับเจ้าของ (ข้อมูลและสิทธิ์เหมือนกัน) ไฟล์ SQL ทดสอบชุดใหม่ยังไม่ได้รัน และยังไม่ได้ใช้กับฐานข้อมูลจริงหรือทดสอบกับ Stripe จริง

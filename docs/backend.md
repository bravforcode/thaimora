# Backend implementation and operating runbook

These files implement the database, Edge API, source jobs, and checks. No hosted account, production deployment, domain, provider credentials, legal approval, inventory rights, or live integration has been verified. Preview fixtures never fulfill launch inventory. The browser receives only explicit public DTOs. Secrets belong in Supabase, the private build environment, or encrypted GitHub secrets.

## Local verification

Run npm run test:backend, then npx deno check --config supabase/functions/deno.json supabase/functions/api/index.ts supabase/functions/deliver-email/index.ts. On Linux/GitHub, bash scripts/test-database.sh starts a disposable Supabase Postgres 15 image, bootstraps test auth roles, applies every migration, runs SQL checks, and destroys its container. This proves PostgreSQL policies and transactions with local synthetic records; it does not prove hosted Supabase Auth/Storage, Turnstile, Resend, provider entitlements, DNS, quotas, or production UAT.

Observed 2026-10-03: Docker daemon 28.3.2, existing Supabase CLI 2.118.0. Full local supabase start first timed out while pulling images; retry raced the original startup and failed its container-name check. Verification instead used one explicitly named disposable Postgres image container with two independent test databases. Do not report those failed startup attempts as a successful local Supabase deployment.

Deno type checks passed with scoped npm resolution. Vitest checks use fake transports and reserved example.test URLs. The database tests roll back their fixtures.

## Hosted setup

The user has requested production deployment and selected Vercel *.vercel.app for the initial frontend host. Use the selected client-owned Supabase and Vercel projects after verifying permitted hosting terms, actual free entitlement and account quotas. Vercel Hobby is restricted to noncommercial personal use; do not treat these commercial sites as eligible or add a card, automatic upgrade, paid routing tier or PAYG. Cloudflare support remains optional. This runbook does not prove deployment occurred; current account selection, real data and live test evidence must be recorded. See docs/deployment.md for the secure local environment loader and explicit gated build/deployment commands.

1. Copy .env.example to an ignored local environment file and populate only client-approved values.
2. Link the existing Supabase CLI to the client project, review migrations, then apply with supabase db push. No CLI upgrade is required.
3. Bootstrap the first admin membership using the client-controlled SQL console after that user signs in through Supabase Auth. Set admin_memberships.user_id to the actual auth.users.id, role='admin'. No default password or publicly writable bootstrap endpoint exists.
4. Set private Edge function secrets through Supabase's secret store. Deploy with supabase functions deploy api. The config disables gateway JWT verification for public browsing; every /v1/admin path separately validates the user's JWT with Auth and checks admin_memberships.
5. Set ALLOWED_ORIGINS to the exact approved site origin(s), RATE_LIMIT_SALT to a random server secret, and restrict browser map/Turnstile keys by hostname. Supply public NEXT_PUBLIC_API_URL ending /functions/v1/api. CORS rejects unknown browser origins.
6. Review source licenses, import actual catalogs, approve gallery rights, verify bilingual content, and complete hosted integration and UAT checks before enabling live mode.
7. Export a production public snapshot with EXPORT_MODE=production npx tsx scripts/export-public-content.ts scripts/output/public-content.json. The export does not query private coordinates, inquiry PII, provider secrets, click logs, or live offers.
8. Set the site-specific snapshot and legal paths, populate reviewed scripts/launch-evidence.json, run the explicit production build command, and review the generated out directory. Do not substitute example evidence for actual signoff.

Database settings contain only nonsecret IDs/configuration. A rights flag is an administrator decision supported by separate provenance/evidence; an API key never proves content rights.

## Source jobs

npx tsx scripts/sync-content.ts tat reads CKAN package_show metadata daily, downloads tourismactivity's activity.json only when the source version changed, accepts its actual uppercase field names and SQL-text-key array root, normalizes Bangkok all-day end dates to exclusive next day, and quarantines invalid records. The approximately 60 MB response belongs in this CLI/GitHub job, never in a request-time Edge function. TAT's exact Open Data Commons license variant remains pending approval; TAT records stay unpublished with rights_status=pending. No future dates are invented.

npx tsx scripts/sync-content.ts poi calls the Geoapify Places API inside configured CONTENT_BBOX. GEOAPIFY_RIGHTS_CONFIRMED remains false until API terms/data rights are approved. OSM-derived raw source data is stored in osm_pois, separately from proprietary inventory, with source URL, license and fetch time. Public attribution must include Geoapify and OpenStreetMap where applicable.

npx tsx scripts/import-pois.ts path/to/licensed-osm-pois.json accepts actual normalized OSM records only after licenseVerified=true in the reviewed source wrapper or POI_LICENSE_CONFIRMED=true. Each record requires an osm: ID, OSM source URL, ODbL attribution, valid coordinate and bilingual name. Store/share the OSM-derived source database and modifications under its applicable ODbL terms; do not relicense proprietary listings or hotels as OSM data.

npx tsx scripts/sync-content.ts fx uses Frankfurter v2 /rates?base=THB daily. The API returns the source date and marks old data stale; converted display currency never replaces the primary THB property price or a provider's actual requested offer currency.

All jobs keep admin_override rows and their rights/publication decisions, use idempotent keys, record sync_runs, and never delete the catalog on a source outage. Failed source data is quarantined with the reason; raw API secrets never enter provenance URLs. No portal or social-media scraping is included.

## Backups and recovery

Supabase Free does not guarantee a daily managed backup. backup.yml creates an encrypted daily logical dump and uploads only the encrypted artifact, with seven-day retention. scripts/backup-db.sh requires PostgreSQL client tools, age, DATABASE_URL, AGE_RECIPIENT, a private AGE_IDENTITY_FILE, and a separate RESTORE_DATABASE_URL explicitly marked disposable. The restore target must not be the live database.

The dump includes public, extensions and auth schemas, including private coordinates and inquiry PII where applicable; encryption and private repository access are mandatory. Storage image objects are excluded and need their own client-owned recovery plan. The script checks the actual encrypted size <=30 MiB, decrypts to pg_restore --list, then performs an actual clean restore on the disposable target before upload. Missing identity/restore tools/target causes failure; a list-only check never counts as restoration.

Two projects x seven days x 30 MiB = 420 MiB maximum encrypted backup artifacts, reserving space under a shared 500 MiB allowance. This is an enforced file-size ceiling, not a prediction of dump size. Other artifacts and repository storage require the shared account audit. AGE private keys are temporary, permission-restricted, removed after the job, and never uploaded.

An actual local fixture drill ran both encrypted dumps and restores: Thaimora 81,689 bytes; TaoTide 60,523 bytes. Restored anonymous column/view/search grants, private RLS, admin access and inquiry idempotency were checked. Source ACLs are preserved. Targets explicitly install PostGIS/pgcrypto; builtin spatial_ref_sys data is excluded because this app uses standard EPSG4326. Custom SRID recovery is outside this runbook. GitHub backups require private repositories and create their own disposable PostGIS Docker target, requiring no third hosted project. Hosted platform ownership/Auth/Storage recovery and daily GitHub execution remain unverified. The target schemas are reset only after explicit disposable confirmation and distinct source/target identity checks. See docs/evidence/backend-verification.txt and docs/verification.md for evidence and observed failures.

## Thaimora contracts and privacy

GET /v1/properties returns {items,nextCursor}; limit is 1..50. Filters: q, transaction, type, minPrice/maxPrice, beds/baths, minArea/maxArea, ownership, furnishing, status, zone, province, amenities as comma-separated tags, bbox west,south,east,north, and polygon as closed GeoJSON Polygon. Sorts: relevance, newest, price_asc, price_desc, area_desc, distance with center=lng,lat. Stable keyset cursors include the sort value and UUID. The database handles bbox, polygon and distance using public_location only; filtering never consults private geom. SQL test fixtures prove complete traversal of 500 records with equal sort values without skipped/duplicate rows.

GET /v1/properties/:id-or-slug returns a raw PublicProperty. GET /:id/nearby uses PostGIS geography from the same safe public point. GET /v1/places/autocomplete?q=&locale= requires Geoapify server credentials; missing configuration returns typed unavailable. GET /v1/content returns approved POIs and future events. GET /v1/fx?base=THB&quotes=USD,EUR provides indicative conversion rates.

Exact coordinates live only in property_private_locations under RLS. Consent evidence permits an exact public API projection; revoking consent immediately recomputes an approximate grid and 300 m radius. The publication trigger checks the projection against the separate private point and verifies bilingual title/description, rights, ownership and an approved gallery with rights evidence. Static exports deterministically coarsen even consented exact PUBLIC projections; they never read private geom. The browser snapshot loader must reject raw exact snapshots. Anonymous users cannot read private coordinates, inquiries, outbox, imports or private settings.

POST /v1/inquiries accepts {name,email,country,message,propertyId,turnstileToken,website?} and an Idempotency-Key header. Empty honeypot, validated Turnstile hostname/action='inquiry', server rate protection and an available published property are required. insert + email_outbox occur in one transaction. Same key/payload returns the saved inquiry without another email; changed payload returns 409. A 202 response means saved with pending email, not delivered. The separately deployed deliver-email worker requires a private EMAIL_WORKER_SECRET, Resend key, approved sender and recipient; it retries failures with backoff and stable provider idempotency. Trigger it from a client-approved secure scheduler every few minutes. Supabase Free function/Resend usage must be monitored; no worker secret appears in a browser.

Admin uses a Supabase Bearer JWT. GET /admin/properties exposes public DTO plus protected publication, privateLocation and gallery fields; GET /admin/inquiries, /imports and /stats returns {items}. Property POST/PATCH accepts flattened snake_case fields published,demo,rights_status,ownership_evidence; privateLocation is nested {lat,lng,exact_publication_consent,consent_evidence}; images include existing id,url,alt,credit,source_url,rights_status,rights_evidence,position. The server owns public projection fields. DELETE removes the property and its dependent private/gallery data, subject to inquiry foreign-key protection. POST /admin/imports accepts {csv,sourceName?,duplicatePolicy?}; duplicatePolicy is skip (default), update or error. The browser parses XLSX with read-excel-file and submits normalized CSV; direct xlsxBase64 is rejected. Server row validation accepts canonical evidence and downloaded-template _url aliases. Valid rows import despite failures; {job,skipped,errors} reports original row mappings in the UI. Blank optional expiry/status/area/floor/year/amenities preserve existing values on duplicate update; deliberate clearing uses the listing editor. Imports remain draft with rights pending. GET /admin/inquiries/export streams safe CSV values with formula-injection prefixes; permissions are checked server-side. Admin POI/event/zone/settings CRUD uses snake_case source fields and explicit publication decisions.

The optional property-images Storage bucket is for sanitized public derivatives only. Its migration executes only when hosted Supabase's storage tables exist. Authenticated admin uploads need user metadata sanitized=true and nonempty rights_evidence, image MIME/type and an 8 MiB limit. Browser processing must strip EXIF before upload and collect rights confirmation. No private original or coordinate metadata belongs in this public bucket. Actual Storage policy and EXIF/UAT checks have not been run.

Catalog import: CATALOG_RIGHTS_CONFIRMED=true npx tsx scripts/sync-hotel-catalog.ts client-properties.json (the filename is shared by the approved automation list). This site's adapter imports PROPERTY records only, keeps them drafts, and requires real ownership/gallery rights evidence and nested privateLocation. Never commit private catalogs or place them in public exports; use a secure runner download/secret-managed source for hosted imports. The 500-property launch gate requires approved real client-owned inventory, not the 30 preview fixtures or SQL test records.

Build environment: NEXT_PUBLIC_DATA_MODE=live, NEXT_PUBLIC_API_URL, NEXT_PUBLIC_ARCGIS_API_KEY restricted by domain, THAIMORA_SNAPSHOT_PATH, and THAIMORA_LEGAL_PATH. Legal JSON: {approved:true,privacy:{en:string,th:string},terms:{en:string,th:string}}, each string at least 100 characters and actually client-approved. A production snapshot has mode='production' and at least 500 public real properties. Preview npm run build needs none of these hosted credentials. Explicit production: npm run build:production (includes the locale repair and final launch gate). All production preflight/postflight failures block launch.

Verified helper suite: 17 tests (boundaries, actual OSM source and preview/production subprocess gates). Actual OSM extract: 1,868 licensed Phuket records validated, without a field survey or hosted import claim. Verified SQL: anonymous browsing/private RLS/admin read, protected evidence columns, consent revocation, spatial non-leak, inquiry/outbox idempotency/conflict/retry, expiry, and 500-record cursor/filter traversal. Verified Deno: API and email-worker entrypoints. Local encrypted restore and restored permissions passed. Hosted email/Turnstile/Auth/Storage/source sync/daily recovery tests remain unrun.
Admin property edits call admin_save_property in one PostgreSQL transaction: draft/location/full ordered gallery/publish/attributed audit succeed together or roll back. Gallery IDs must belong to the same listing, ownership is immutable, omitted images are removed, and approval requires existing written rights evidence. NULL or blank exact-consent evidence is rejected. Deleting a private location clears its public projection and unpublishes the listing. Anonymous and unaffiliated authenticated browsing cannot select protected evidence columns. POI/event public views require non-demo, approved rights, HTTPS source and a documented license.

POST /v1/analytics/events accepts {propertyId,kind:view|contact_click,consented:true}; unconsented submissions are rejected. GET /v1/admin/stats?from=YYYY-MM-DD&to=YYYY-MM-DD returns inclusive daily aggregates in Asia/Bangkok, bounded to 365-day difference; no unique visitor claim. Admin audit metadata stores allowlisted changed field names and actor/resource/time, never field values, private coordinates, API secrets or inquiry PII.
